Architecture Guide & Takeaway

ShikshaGap — Code Tour & App Map

A reference map of the client-side diagnostic assessment app, its verified data flow, and key practices to reuse.

🎯 Purpose & System Overview

ShikshaGap diagnoses foundational mathematics gaps in Class 5 students. When a student struggles with adding unlike fractions, it dynamically steps back to isolate whether the failure stems from equivalent fractions or multiplication fact recall.

The app is split into two completely decoupled layers: a pure diagnostic engine tested against 17 automated acceptance criteria, and a lightweight React view layer with instant click-locking and accessible dual feedback.

🔄 Verified End-to-End Data Flow

📍 Reference Code Route (3 Key Stops)

Stop 1: Curated Mathematical Bank

src/data/questions.ts

Contains all 12 curated questions across Level 3, Level 2, and Level 1. Each question stores correctValue: string rather than a static option position, allowing options to be shuffled dynamically without corrupting the correct answer.

View verification tests for this stop

src/data/questions.test.ts verifies: 1 correct option per question, 4 distinct values and texts, exact math solutions evaluated via code, and $\ge 4$ questions per level.

Stop 2: Pure Diagnostic State Machine

src/engine/diagnosticEngine.ts

Exports pure functions startQuiz, submitAnswer, and resetQuiz. Contains zero DOM or React imports, never calls Math.random() internally, and requires an explicit rng: () => number parameter.

View decision rules for this stop

Evaluates Level 3 (advances or steps back to L2), Level 2 (verdicts L3 gap or steps back to L1), Level 1 (slip-check confirmation or L1 gap verdict), and enforces the hard 6-question cap.

Stop 3: Accessible Component Views & Audit Trail

src/components/

OptionCard.tsx enforces immediate click-locking on first tap and renders dual icon/text accessibility labels. ResultView.tsx maps the engine's auditTrail into a human-readable list explaining why each question was asked.

🛠️ To Change This, Start Here

  • To add or modify math questions: Open src/data/questions.ts. Add new entries with verified correctValue and run npm test to ensure data validation passes.
  • To adjust diagnostic branching logic: Open src/engine/diagnosticEngine.ts inside the submitAnswer function.
  • To modify colors or touch targets: Open src/index.css and adjust the custom properties under :root.
  • To change project metadata: Open package.json (renamed to shikshagap-poc).

💡 A Practice to Reuse: Anti-False-Positive Diagnostic Testing

When collaborating with AI coding agents, agents can easily produce "false positives" where tests pass only because mock data always returned option A or transitions were never tested under edge conditions.

The reusable technique applied here: Decouple state logic into a pure, parameter-injected engine module, test option selection using semantic helpers (answerCorrectly/answerWrongly) rather than fixed letters/indices, and perform a recursive tree walk (INVAR-1 & INVAR-2) to mathematically guarantee termination boundaries before writing a single line of UI code.

  • npm test — Executes full 17-test Vitest suite in single-run mode
